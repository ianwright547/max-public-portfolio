# Reporting

## Purpose

Max produces factual internal and client-facing reports from saved client records, verified work, historical metrics, findings, and evidence.

## Report types

### Internal report

Include:

- Health status
- Access issues
- Findings and evidence
- Task status
- Failures and blockers
- Costs
- Risks
- Pending approvals
- Data-source labels

### Client report

Include:

- Service start date and time with the agency
- Starting baseline
- Previous results
- Current results
- Verified completed work
- Measurable changes
- Unresolved issues
- Simple next steps

## Data rules

Clearly label manual, mock, imported, and live data.

Never manufacture results, revenue, leads, rankings, causes, or completed work.

Proposed, approved-but-unexecuted, completed-but-unverified, failed, and blocked work must not be described as verified completed work.

Negative changes and failures must remain visible and use respectful language.

## Calculations

Application code calculates:

- Totals
- Absolute changes
- Percentage changes
- Baseline comparisons
- Previous-period comparisons
- Completed and open task counts

AI may explain calculated results, but it must not change the numbers.

## Healthy reports

A healthy client may receive a simple report stating that monitoring found no necessary action.

Do not create unnecessary work merely to make a report appear busy.

## Versioning and approval

Reports are immutable snapshots. Corrections create a new report version.

Reports should be reviewed before client delivery. The saved report must include its source records and data labels.

## Final checklist

- Correct client?
- Correct period?
- Baseline present?
- Current and previous results included?
- Sources labeled?
- Negative changes visible?
- Only verified work described as completed?
- Evidence linked?
- Next steps supported by facts?
- Report version preserved?
